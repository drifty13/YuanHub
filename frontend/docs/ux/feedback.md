# 反馈中心

## 统一反馈中心

玩家从 `/feedback` 查看自己的全部人工反馈，提交时选择一次「相关功能」。选项来自开放产品的可见板块，提交按所选板块的真实归属派单。MaaYuan 使用既有 `MAAYUAN` 板块。该板块可用时，创建表单收起旧 `maayuan` 专区的通用「其他问题」，保留其具体功能及历史记录。

旧 `?space=maayuan` 入口打开表单时预选麻圆，玩家可以改选。其他合作入口只有一个可选板块时预选该项；多个时由玩家选择。含明确板块的链接优先采用该板块。旧工单链接仍按编号打开。

反馈广场已下线。旧 `/feedback/plaza` 分享链接跳转到 `/feedback`，丢弃原查询参数。

工作台 `/feedback/manage` 默认显示本人全部授权范围的队列及计数，按负责板块筛选；在管理操作与列表设置中可收窄到具体专区，旧工作台专区链接仍限定该范围。

管理反馈未读按真实工单归属分组，不再定时轮询；功能切换（path 变化）时，仅在存在订阅者且有管理读取权限时查询，复用 15 秒新鲜度和在途合并。身份/权限变化及原有写入后的刷新保留，反馈工作台自身每 30 秒的列表刷新不变。当前专区“全部已读”包含筛选之外的本专区工单，不影响其他专区。所有专区总管理有明确作用范围说明。工单详情、回复、处理与合并关系继续复用原组件和岗位约束。

既有 `/feedback/admin` 的折叠“专区设置”承载创建、改名、开放状态与合作入口；成员通过同页既有岗位/板块授权配置。全局岗位不因切换专区自动变化，保存当前专区板块时保留其他专区已有授权；删除整份授权会明确提示作用于全部专区。仅拥有既有授权配置权限者可修改，不给普通专区成员额外配置权。创建/修改可在原审计页追溯。

新反馈图片使用私有上传，详情鉴权下载并在离开时释放临时地址；普通文件能力与 10 个混合附件上限保留。**旧 `/media/` 图片地址未迁移，仍有原公开访问边界**，详见后端反馈接口文档。合作专区没有独立版本目录，不复用主站草稿版本。

新建反馈、用户追加消息和管理员回复，每条消息最多添加 10 个附件，截图与普通文件合计计数。选择器显示当前数量与上限，超过上限时保留原附件并提示。

反馈图片采用清晰度优先的有损压缩：超过 128 KiB 后优先编码为 WebP，质量从 0.84 调整到最低 0.78，目标 512 KiB、前端上传上限 3 MiB。保留原始像素尺寸与长宽比例，不再把长截图缩到 2560 像素；编码反而增大且原图不超过 3 MiB 时保留较小的原图。压缩后仍超限会提示裁剪无关区域或拆成多张截图，不继续降低质量或缩小尺寸。原文件 25 MiB、4000 万像素、单边 12000 像素的处理边界保留。缩略图与点击打开大图的入口不变，上传后只保存最终选中的图片，并非同时保留未经压缩的原图；历史附件不重新压缩。实际小字可读性与放大查看仍需人工验收。

上述 3 MiB 是当前前端的图片规则；后端通用媒体接口仍为 10 MiB，旧客户端或直接调用接口不受此前端策略约束。TXT、LOG、JSON、PDF、ZIP 普通附件仍为每个 10 MiB，头像与更新公告沿用各自压缩策略。

手机选图、粘贴或拖入图片时，优先按文件头识别 JPG/JPEG、PNG、WebP。文件名缺少后缀，或后缀、MIME 与实际格式不符时，会先校正文件名和 MIME，再沿用现有压缩规则。文件头无法识别时沿用原有的后缀和 MIME 校验。识别到 HEIC/HEIF 时，本批附件不会加入，并提示在相册中截图或导出为 JPG 后再添加。服务端仍校验文件头。

桌面侧栏与手机导航抽屉均直接展示「反馈中心」，位于活动日历后，不再收在「更多」中。入口统一指向 `/feedback`，游客登录后进入我的反馈；该入口不显示管理员待阅反馈角标，也不订阅管理反馈未读。管理员待阅状态在反馈工作台内查看，个人回复提醒仍通过站内通知与我的反馈列表显示。反馈页面高亮独立入口，管理页面仍归属管理工作台。

我的反馈、反馈工作台和权限配置各有独立路由与紧凑页头。管理员通过全站导航的「管理工作台」进入「待处理反馈 / 反馈授权」，入口按账号权限显示。

我的反馈在请求成功确认没有工单、且没有筛选条件时收起搜索、筛选和页码，优先展示「提交第一条反馈」。筛选无结果保留控件并可清除条件；加载中或失败时不会被误判为空态，重试和权限错误提示仍可访问。手机端压缩页头与空态留白，空态说明使用常规字重。搜索、工单状态与板块筛选形成连续区域，不展示反馈类型。OPEN 始终表示处理中；新消息标识来自通知记录，不因历史 hasAdminReply 一直显示已回复。列表优先显示标题，私人列表的编号折叠展示。

公开功能计划成功确认无筛选且没有目标时收起阶段工具栏与进度解释，保留提交建议入口；阶段筛选无结果保留控件与「查看全部目标」，请求失败保留筛选和重试，管理视图仍保留工具栏。完成标准来自开发目标数据。

新建反馈仅需选择服务端动态板块并填写内容，普通提交固定 `type=OTHER`，不展示类型选择。板块支持自定义及重命名，目录失败时禁止提交。旧链接继续解析实际可用板块（含活动日历 `builtin_key`），类型参数不改变普通提交类型，不复制链接中的正文。新反馈仅用于私下沟通，提交时固定 `public_consent=false`，无需标题。附加浏览器、操作系统和 IP 信息的选项默认关闭，收在可选设置。表单单列，紧凑附件，长内容内部滚动，底部取消/提交保持可达。

反馈工作台已移除发布入口。兼容的管理员 API 继续按原权限与历史公开授权校验。举报只供授权人员私下处理。

关闭未提交的草稿仍需确认。表单支持 Tab 焦点限制、Esc 关闭及关闭后返回入口。

「标记完成」表示问题已解决并结案，不能继续追加消息；确认框会说明这一后果。结案确认统一说明工单后果，管理员接口仍按原默认值处理历史公开状态。提交成功后说明回复将通过站内通知送达。

管理员工作台按当前搜索和负责板块显示各队列总数，数量来自服务端分页总数，失败时显示「—」和重试提示。「已接单」展示授权板块内所有运营接的单。打开「只看待回复」可查看玩家最后一条消息后还没有管理员回复的工单，也可叠加「只看我的」；列表、总数和分页同步收窄。默认按最新提交排序，也可选择最近更新或最早提交；最早提交不等同于用户等待回复时长。

回复文字、附件和流转说明在取消、关闭详情、切换工单/筛选、离开路由及刷新页面前受草稿保护。拒绝放弃时保留正文、附件和原筛选值。回复表单打开后聚焦输入框，详情、合并与权限弹窗限制 Tab 焦点，Esc 关闭最上层，关闭后返回入口。处理记录仍位于原有「工单流转」菜单，入口条件不变。

管理员回复框提供「插入当前版本」按钮，旁边显示当前页面加载的前端产品版本（与侧边栏一致）。点击后在光标位置插入版本号，选中文字时替换所选内容，并返回输入框继续编辑；例如「该功能已于 v0.0.1-beta.15 实现」。插入不会自动发送，不使用用户提交反馈时的旧版本；插入后超过 1000 字符会提示并保留原文，发送期间按钮不可用。更新发布后应先刷新页面，再插入新版本。

完成、驳回和重新打开使用明确的确认文案，成功后显示结果并保留筛选、排序和有效页码；原页消失时回退至最后有效页。管理列表优先显示两行摘要、待办状态、负责人及更新时间，编号折叠后可复制；手机列表保留状态和进入详情的操作。

「全部管理范围已读」收在「管理操作与列表设置」中，与列表筛选分开呈现，确认框说明数量及包含筛选之外的工单，只更新阅读状态，不结案。界面不再展示或维护反馈类型；底层枚举及内部兼容 API 保留。合并弹窗展示来源及主反馈，搜索或来源改变立即清除旧选择，旧请求不能覆盖最新结果。

权限页优先展示运营岗位与负责板块；通知接收及兼容管理授权放在折叠区域，预览和保存仍保留全部授权。通知、兼容管理和工作台岗位分别生效，不自动授予岗位或覆盖岗位板块。

反馈授权表的「编辑」和「删除」固定在每行末尾。平板按可用宽度换行展示岗位、板块和更新时间，可直接点按操作。


## 轻量工作台与人工验收（2026-10-16）

主要入口为待接单、已接单，次级入口为已结束、全部。已接单每行显示运营负责人和「待回复」或「已回复」。每页数量收在列表设置；搜索/板块/排序保留原服务端筛选、总数与有效页码逻辑。

桌面表格按反馈内容、板块、待办/状态、负责人、更新时间、查看工单排列。未分配负责人不再重复显示待接单。编号可展开及复制，新消息未读与需回复分别来自 teamUnread 和 needsReply。手机为纵向卡片，队列可横向滚动，不新增底部导航。

以下均为**待人工验收**，非浏览器自动化结果：

1. **1440px**：打开 `/feedback?new=1`，只选板块填正文即可私下提交。添加/粘贴截图、文件，核对失败提示、重复提交防护、取消草稿确认及成功反馈。客户端信息默认关闭。
2. **390px**（同时抽查 320/430px）：新建弹窗单列、正文独立滚动，操作按钮位于正文滚动区之外；展开客户端设置后按钮仍可到达。点击正文输入框并唤起软键盘，当前输入应可见，继续输入多行、收起键盘和横竖屏切换后草稿与焦点不丢。工作台显示卡片，队列区域可独立横向滚动，整页不横向溢出。
3. **768/1024px**（补查 1199/1200px）：搜索、板块、排序、状态和队列入口可直接使用。长标题换行，长自定义板块、负责人和工单编号不撑开容器，「查看」可直接点到。切换宽度后检查草稿、焦点、下拉菜单和详情关闭时的焦点返回。
4. **工作台**：检查运营仅可见授权板块、超级管理员可见全部，默认进入待接单；接单、回复、接手、转交运营、调整板块、结案/重开、合并沿用现有权限。筛选后打开管理设置，全部已读确认必须明确包含筛选之外工单。
5. **隐私与兼容**：旧日历链接能预选重命名板块；不同历史类型仍可打开/回复。旧广场地址丢弃查询参数并进入反馈中心。工作台没有发布入口，更新日志没有关联反馈区。

新建弹窗沿用日历软键盘修复（`10d48a1`）的方式：打开期间跟随 `visualViewport` 高度与顶部偏移，视口变化时只调整正文滚动位置；正文框在短视口下限制高度，保留内部文本滚动。没有该 API 时回退窗口高度，关闭或卸载后移除监听。未修改全局缩放、输入字号及其他弹窗。


## 反馈板块隐藏与恢复

超级管理员在「反馈权限 → 反馈板块」点击「隐藏」或「恢复显示」。隐藏项标注「已隐藏」，留在板块管理列表中供恢复；用户新建/筛选、管理员筛选/调整板块和各类授权选择不再提供该项。历史工单名称和原有授权保留；编辑授权后也不会因选项隐藏而丢失旧权限。隐藏属于展示控制，不代表撤销权限或禁止直接 API 提交。全部板块隐藏时显示「暂无可选相关功能」并禁用提交，不阻断历史列表。

用户验收（390px、1440px）：隐藏一个已有历史反馈及授权的板块，刷新个人反馈和管理工作台，确认选择中消失、历史名称仍在；编辑并保存原授权，确认权限未丢失；回板块管理恢复显示，再刷新确认可选。再检查全部隐藏后仍可恢复且无加载失败提示。真实布局、触控和浏览器运行时由用户手动验收。

最小定向验证（在 YuanHub 目录）：
