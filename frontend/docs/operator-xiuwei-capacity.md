# 库存可养人数

登录并选中子账号，在 `/operator` 的「养成规划」页头打开「更多」→「培养储备」，选择「库存可养人数」。可在面板底部切到「储备方案」，添加多位密探的培养目标一起估算材料。

起始、目标修为默认 1→17，修改后即时计算，目标必须高于起始。同一次页面会话中，切换视图或返回养成规划再进入会保留条件和展开组。切换子账号或游戏会关闭工作区并重置试算条件。条件只保存在本次页面会话。

## 计算口径

复用现有修为费用规则，分别显示风火、地水、阴阳三组。风、火共用同一份扇类材料，人数为风火合计，其他组同理。所有人都按同一个修为区间估算，不推断具体密探现有练度，也不统计实际拥有多少位密探。混沌无已知费用规则，暂不试算。

对该区间需要的每种材料取 `floor(当前库存 / 单人需求)`，最小值即该组人数 N。用不到的材料不限制人数。培养 N 人后的剩余为 `库存 - N × 单人需求`；再养一人的缺口为 `max(单人需求 - 剩余, 0)`。零人时展示培养第一人的缺口。

阴阳 13→17 示例：单人需宝石镜 940、水镜 2760、星汉镜 2100。库存分别为 3000、8000、5000 时可供 2 人，剩余 1120、2480、800；再养一人缺水镜 280、星汉镜 1300。

仅衡量修为材料，等级需满足解锁条件，五铢钱、兵书和等级突破材料另计。使用完整当前库存独立试算，不扣其他计划的需求、不预留或消费库存，不创建真实密探、培养目标、日程或升级交易，不对接 Maa 自动执行/计数。

## 库存与交互

面板中的库存刷新只触发库存读取。同步期间隐藏旧人数，读取失败或数量非法时显示错误与重试入口。成功读取的空库存按 0 人处理。

桌面为三张结果卡与五列用料表，手机为三行展开结果，均展示单人需求、库存、培养后剩余、下一人缺口和历练建议。一次只展开一组。点击「返回养成规划」后，焦点回到页头「更多」。下拉展开时可按 Escape 收起下拉。

## 验证范围

定向 Node 测试覆盖人数瓶颈、整数边界、共用属性组、缺口、非法或未知库存和区间。Vitest/jsdom 用例覆盖即时试算、刷新、错误恢复、返回焦点、无需培养清单、只读边界及账号切换时的迟到响应。

人工验收时，以 390px 和 1440px 打开面板并选择 13→17，依次展开三组、刷新库存、切换视图并返回养成规划后重进。补查 320px、767/768px 切换、手机横屏及深色主题。确认内容可读、无横向溢出、底部切换按钮可达，原清单和日程仍可正常编辑。
